Exercise walkthrough

What each exercise is really asking, and how the seven fit together. This explains the mechanisms, not the implementations — the code is yours to write, and reading someone else's answer is the one way to get nothing out of this lesson.

The seven come in pairs. Each pair does the same maths twice: once by hand so you own it, once vectorised so you can use it.

1 and 2 — the dot product, by hand and vectorised

Exercise 1 is the definition as an algorithm: walk both lists together, multiply each pair, accumulate. The stepper near the top of this page is exactly what your loop does, one iteration per click. The length check matters because the operation is undefined for mismatched lengths — there is no sensible answer, so failing loudly beats guessing.

Exercise 2 is the same result with the loop pushed into compiled C. Worth knowing: np.dot and np.matmul (also spelled @) agree for 1-D inputs but diverge for higher dimensions — np.dot sums over the last axis of one and the second-to-last of the other, while matmul broadcasts stacks of matrices. For two vectors, either is right.

3 and 4 — magnitude is just Pythagoras

Nothing new is happening here. The length of [3, 4] is the hypotenuse of a right triangle with legs 3 and 4.

Exercise 4 is the same sum, vectorised. np.linalg.norm exists and does it in one call — but write it out at least once, because seeing square, sum and sqrt compose is how the vectorised style starts to feel natural.

5 — normalise: keep the direction, throw away the length

Dividing a vector by its own magnitude leaves it pointing exactly where it was, with length precisely 1. Every such vector lands on the unit circle.

6 — cosine similarity, and why the division works

One identity sits underneath the whole exercise:

a · b  =  |a| × |b| × cos θ

The dot product was never purely about agreement — it is agreement scaled by both lengths. That is precisely the flaw demonstrated earlier: pressing × 2 doubles the number without turning the arrows at all. Divide both sides by |a| × |b| and the lengths cancel, leaving the angle alone. You are not inventing a metric; you are rearranging an identity to isolate what you actually wanted.

The name is not decoration either. cos(0°) = 1, cos(90°) = 0, cos(180°) = −1 — the function already had the range and the meaning we wanted. Nobody designed that; it fell out.

7 — search, and the version you have not written yet

Exercise 7 is short because exercise 6 did the work. The one piece of Python worth pinning down is max(scores, key=scores.get): iterating a dict yields its keys, and key= changes what gets compared, not what gets returned. So the comparison runs over scores while the return value is a name. Reaching for max(d.values()) instead gives you 0.998 with no way back to which item earned it.

That solution is the definition. It is not the implementation a real system uses.
