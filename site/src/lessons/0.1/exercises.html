The constraints are the lesson

The tests inspect your source, not just your return value. Exercises 1 and 3 reject NumPy because you are meant to build the mechanism before you are allowed to call it. Exercises 2 and 4–7 reject for loops because writing a Python loop over a NumPy array is the most common beginner mistake in this field, and it costs roughly 200× in speed.

Recognition and production are different skills, and only one of them transfers.

If you are stuck: re-read the docstring, print .shape and the intermediate values, or solve a smaller version by hand on paper first. Open these once your tests pass, to compare — not to get unstuck.

Exercise 1 — dot_loop 
def dot_loop(a: list[float], b: list[float]) -> float:
    if len(a) != len(b):
        raise ValueError("The lengths of the two lists must be equal.")

    total = 0.0
    for i in range(len(a)):
        total += a[i] * b[i]
    return total

The accumulator starts at 0.0 rather than 0 so the return type is a float even for integer inputs. Indexing with range(len(a)) is the one place in this lesson where an index is genuinely needed — you are walking two lists in step.

Exercise 2 — dot_numpy 
def dot_numpy(a: np.ndarray, b: np.ndarray) -> float:
    return float(np.dot(a, b))

np.matmul(a, b) and a @ b are equally correct here. They agree with np.dot for 1-D inputs and diverge only in higher dimensions. The float() matters more than it looks: without it you return np.float64, which behaves almost like a Python float right up until it does not — it will not JSON-serialise, and it leaks numpy semantics into code that expected a plain number.

Exercise 3 — magnitude_loop 
def magnitude_loop(v: list[float]) -> float:
    squared = [x ** 2 for x in v]
    return math.sqrt(sum(squared))

A comprehension plus sum() is idiomatic Python and allowed here — exercise 1 already proved you can accumulate by hand, and the point of this one is Pythagoras. sum(x ** 2 for x in v) using a generator instead of a list is marginally better for very long inputs, since it never materialises the intermediate list.

Exercise 4 — magnitude 
def magnitude(v: np.ndarray) -> float:
    return float(np.sqrt(np.sum(np.square(v))))

np.linalg.norm(v) does the same job in one call and is what you would reach for in real code. Write it out at least once, though — seeing square, sum and sqrt compose into a single expression is where the vectorised style starts to feel natural. Neither version survives extreme inputs: both overflow to inf around 1e200, because both square before summing.

Exercise 5 — normalise 
def normalise(v: np.ndarray) -> np.ndarray:
    length = magnitude(v)
    if length == 0:
        raise ValueError("Cannot normalise a zero vector.")
    return v / length

Calling magnitude(v) rather than rewriting the formula gives you one source of truth. Naming the local length and not magnitude matters — a local of the same name shadows the function, and the next person to add a second call inside this function gets a confusing TypeError.

Exercise 6 — cosine_similarity 
def cosine_similarity(a: np.ndarray, b: np.ndarray) -> float:
    a_magnitude = magnitude(a)
    b_magnitude = magnitude(b)
    if a_magnitude == 0 or b_magnitude == 0:
        raise ValueError("Cannot compute cosine similarity with a zero vector.")
    return float(np.dot(a, b) / (a_magnitude * b_magnitude))

The zero check is not required by the tests, but the cosine of an angle with a directionless vector is genuinely undefined, so raising beats returning a made-up number.

np.dot(normalise(a), normalise(b)) is equally correct and returns the identical value bit for bit — the second route from the walkthrough. It is shorter and inherits the zero-vector check from normalise for free. The version above was chosen only because it mirrors the formula in the docstring. Watch out for the trap in between: calling normalise where you meant magnitude gives you an array where a scalar belongs, and if array == 0 raises "the truth value of an array with more than one element is ambiguous".

Exercise 7 — most_similar 
def most_similar(query: np.ndarray, library: dict[str, np.ndarray]) -> str:
    scores = {name: cosine_similarity(query, vector) for name, vector in library.items()}
    return max(scores, key=scores.get)

Iterating a dict yields its keys, and key= changes what gets compared, not what gets returned — so the comparison runs over scores while the return value is a name. max(scores.values()) would hand you 0.998 with no way back to which item earned it.

This is the definition, not the implementation. See the walkthrough tab, and stretch.py, for the single-matmul version a real system uses.
