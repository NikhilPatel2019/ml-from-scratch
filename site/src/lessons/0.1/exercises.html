The constraints are the lesson

The tests inspect your source, not just your return value. Exercises 1 and 3 reject NumPy because you are meant to build the mechanism before you are allowed to call it. Exercises 2 and 4–7 reject for loops because writing a Python loop over a NumPy array is the most common beginner mistake in this field, and it costs roughly 200× in speed.

Optional: the stretch

Exercise 7 is the definition of similarity search — one cosine per item. It is not the implementation a real system uses. stretch.py in the same folder asks for that version: stack the whole library into a matrix and score every row in a single operation, with no loop and no comprehension anywhere.

terminal
python lessons/00-foundations/01-vectors/stretch.py

It is self-contained and not wired into progress, so it cannot affect your score. It forces you into axis= and keepdims= — where nearly everyone's first silent shape bug lives — and it carries a real design decision in its comments: whether to normalise the library once at write time or divide on every query. That is the trade-off every vector database actually makes.
