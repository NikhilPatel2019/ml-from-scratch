Every one is checked for shape

A right answer in the wrong shape is this lesson's characteristic bug, so the tests assert the output shape as well as the values. When one fails, read the shape line first — it usually says exactly what went wrong.

Build each one in stages

Every exercise past the second is two or three operations composed. Do not write the whole line and then debug it. Write one operation, print its .shape, check it is what you predicted, then add the next.

That loop feels slow for about ten minutes and then stops being slow, because you start predicting correctly. It is the single habit this lesson exists to build.

What the tests check that you might not

  • Shape follows the rows, not the columns. Exercise 2 is tested on a 4×3 as well as a 2×2, so a divisor lined up the wrong way cannot pass by coincidence.
  • Centring moves the data without changing its spread. Checked by confirming the differences between rows are identical before and after.
  • Directions survive normalisation. Every row of the result must be a positive multiple of the row it came from — scaling a row must not turn it.
  • The Gram matrix equals its own transpose. Row i dotted with row j is the same number as row j dotted with row i, so anything else means the pairing went wrong.
  • The distance matrix has a zero diagonal. A row is zero distance from itself. If your diagonal is not zero, your indices are crossed.
  • Scaling the library must not reorder a cosine ranking. Exercise 7 is tested with rows scaled by 90×, because cosine is supposed to ignore exactly that.

Then run the demo

Once all seven pass, run the file directly. It pushes six documents through every function so you can watch the shapes change, and finishes by ranking them.

python lessons/01-foundations/03-matrices/exercises.py

The stretch, if you want it

stretch.py is optional and not scored. Two measurements: how much faster rank_all is than the one-at-a-time version you wrote in 1.1, and what the (n, n, d) intermediate in exercise 6 costs in memory.

The second one matters more. It is the reason production systems do not use the expression you just wrote, and the file walks you to the identity they use instead.
