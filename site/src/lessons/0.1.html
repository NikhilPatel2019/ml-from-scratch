Why we start here

Strip away every buzzword and machine learning is three claims:

  1. Anything can be turned into a list of numbers. A house, a customer, a photograph, the word "banana".
  2. Once things are lists of numbers, "similar" and "different" become arithmetic — and arithmetic is something a computer does a trillion times a second.
  3. A model is a large pile of numbers that you adjust until its outputs stop being wrong.

Phase 0 makes claims 1 and 2 concrete. Today is claim 1, plus the single operation that claim 2 rests on.

That operation is the dot product. To be precise about how central it is: a neuron in a neural network is a dot product followed by one simple function. Attention — the mechanism behind every modern large language model — is dot products. Semantic search is dot products. When a model has 175 billion parameters and needs a GPU cluster, what that hardware is doing, almost exclusively, is dot products.

There is no second idea in this field of comparable importance. You will implement it today in about four lines.

Three gotchas that will bite you:

  • Indentation is syntax. Four spaces. A misindented line is a different program, not a style violation.
  • / is always float division. 5 / 2 == 2.5. Integer division is //.
  • ** is exponentiation. x ** 0.5 is a square root.

A vector is a list of numbers

Genuinely — that is the whole definition. [3, 4] is a vector. [0.2, -1.7, 0.0, 5.5] is a vector. In code it is an array.

The word sounds intimidating because physics teaches it as "magnitude and direction, drawn as an arrow". Set the arrows aside for a moment. A vector is an ordered list of numbers where each position means something fixed.

The interesting half is the second one — each position means something fixed. That is what turns a list into a representation:

house    = [1500, 3, 12]     # [square feet, bedrooms, age in years]
another  = [1600, 3, 10]
mansion  = [8000, 7,  2]

Position 0 is always square footage. Position 1 is always bedrooms. Now these three lists are comparable, and "is this house like that house" has become a maths problem.

That is the entire trick, and every ML system is built on it. Deciding what goes in each position used to be a job title — feature engineering, covered in lesson 1.10. The revolution of deep learning is that networks now learn what the positions should mean instead of you specifying them.

Dimensions just means "how many numbers are in the list". The house vector is 3-dimensional. Sentence embeddings in a modern LLM are typically 768 to 4096-dimensional. You cannot picture 4096 dimensions and you should stop trying — but every operation you learn in 2D works identically in 4096D, unchanged. That is the gift: intuition is built cheaply in two dimensions and then transfers for free.

The dot product

Take two vectors of the same length. Multiply them position by position. Add up the results. One number falls out.

That is the entire operation. As an algorithm: walk both lists together, multiply each pair, accumulate the total. Exercise 1 asks you to write exactly this, with no help from NumPy.

What the number means

This is the part that matters, and where most people's understanding stays shallow.

The dot product measures agreement. Look at what happens to each term in the sum:

SignsContributionReading
both positivepositivethey agree
both negativepositivethey agree, in the other direction
one of eachnegativethey disagree
either is zeronothingno opinion

So the total answers: across all these dimensions, do these two vectors tend to go the same way? This is much easier to feel than to read, so here are the arrows I told you to set aside. Drag them.

The case worth pausing on is the one in the middle. A dot product of zero means "these two things have nothing to say about each other". In geometry that is a right angle. In machine learning it is "unrelated concepts". Same fact, two vocabularies.

Why this is the atom of the field

A neuron in a neural network does exactly this:

output = activation( inputs · weights + bias )

The weights are a vector the network learned. The dot product asks "how much does this input agree with the pattern I have learned to look for?" A high number means "strong match — fire".

That is what a neuron is. Everything else in deep learning — layers, depth, attention, transformers — is about arranging billions of these agreement checks so that useful patterns emerge. When you build a network from scratch in Phase 2, you will be stacking today's function.

The flaw, and the fix

The dot product has a bug as a similarity measure: it is inflated by magnitude. If you pressed × 2 in the demo above, you already saw it — the dot product doubled while the arrows did not turn at all.

[1, 0] · [100, 0]  =  100
[1, 0] · [  1, 0]  =    1

Both pairs point in precisely the same direction. The first scores 100× higher purely because one vector is bigger. If those were documents, a long document would beat a short one on every query regardless of topic. Not what you want.

The fix is to divide out the magnitudes. The magnitude (also called length, or norm) is Pythagoras extended to any number of dimensions — square everything, sum, take the root:

|[3, 4]|  =  √(3² + 4²)  =  √25  =  5

Divide the dot product by both magnitudes and you get cosine similarity:

cos_sim(a, b)  =  (a · b) / (|a| × |b|)

The answer is now always between −1 and 1, and magnitude is gone. Only direction survives:

ValueMeaning
1.0identical direction
0.7strongly related
0.0unrelated, perpendicular
−1.0opposite

Why NumPy exists

Python is slow, and it is worth knowing precisely why, because "NumPy is optimised" is not an answer — it is a way of not having one.

Every value in a Python list is a full heap object carrying a type pointer and a reference count, and the list holds pointers to them. Adding two of them means following a pointer, checking a type, unboxing a number, adding, then allocating a new object for the result. NumPy stores the raw numbers side by side in one block of memory and pushes the loop into compiled C, where one instruction can operate on several values at once.

The vectorised mental model
import numpy as np

a = np.array([1.0, 2.0, 3.0])
b = np.array([4.0, 5.0, 6.0])

a + b        # array([5., 7., 9.])   elementwise, no loop
a * b        # array([4., 10., 18.]) elementwise multiply, NOT matrix multiply
a * 2        # array([2., 4., 6.])   the scalar broadcasts across the array
a.sum()      # 6.0
a.shape      # (3,)  — check this when confused. always.

The mental shift, and it is a real one coming from imperative code: stop thinking "for each element, do X". Start thinking "apply X to the whole array".

The most common beginner mistake

Writing a Python for loop over a NumPy array costs roughly 200× in speed. The tests in this lesson reject it outright. Once all seven pass, run the benchmark and see the gap on your own machine.

Exercise walkthrough

What each exercise is really asking, and how the seven fit together. This explains the mechanisms, not the implementations — the code is yours to write, and reading someone else's answer is the one way to get nothing out of this lesson.

The seven come in pairs. Each pair does the same maths twice: once by hand so you own it, once vectorised so you can use it.

1 and 2 — the dot product, by hand and vectorised

Exercise 1 is the definition as an algorithm: walk both lists together, multiply each pair, accumulate. The stepper near the top of this page is exactly what your loop does, one iteration per click. The length check matters because the operation is undefined for mismatched lengths — there is no sensible answer, so failing loudly beats guessing.

Exercise 2 is the same result with the loop pushed into compiled C. Worth knowing: np.dot and np.matmul (also spelled @) agree for 1-D inputs but diverge for higher dimensions — np.dot sums over the last axis of one and the second-to-last of the other, while matmul broadcasts stacks of matrices. For two vectors, either is right.

3 and 4 — magnitude is just Pythagoras

Nothing new is happening here. The length of [3, 4] is the hypotenuse of a right triangle with legs 3 and 4.

Exercise 4 is the same sum, vectorised. np.linalg.norm exists and does it in one call — but write it out at least once, because seeing square, sum and sqrt compose is how the vectorised style starts to feel natural.

5 — normalise: keep the direction, throw away the length

Dividing a vector by its own magnitude leaves it pointing exactly where it was, with length precisely 1. Every such vector lands on the unit circle.

6 — cosine similarity, and why the division works

One identity sits underneath the whole exercise:

a · b  =  |a| × |b| × cos θ

The dot product was never purely about agreement — it is agreement scaled by both lengths. That is precisely the flaw demonstrated earlier: pressing × 2 doubles the number without turning the arrows at all. Divide both sides by |a| × |b| and the lengths cancel, leaving the angle alone. You are not inventing a metric; you are rearranging an identity to isolate what you actually wanted.

The name is not decoration either. cos(0°) = 1, cos(90°) = 0, cos(180°) = −1 — the function already had the range and the meaning we wanted. Nobody designed that; it fell out.

7 — search, and the version you have not written yet

Exercise 7 is short because exercise 6 did the work. The one piece of Python worth pinning down is max(scores, key=scores.get): iterating a dict yields its keys, and key= changes what gets compared, not what gets returned. So the comparison runs over scores while the return value is a name. Reaching for max(d.values()) instead gives you 0.998 with no way back to which item earned it.

That solution is the definition. It is not the implementation a real system uses.
