The one that costs people an afternoon

Exercise 2 is the whole lesson's pinch point, and it is not about transformations at all — it is about two conventions meeting. A transformation matrix is written to act on a single vector standing up as a column. Your data, since 1.3, lies down: one thing per row.

Resist trying both orders until one stops raising. On a square matrix both orders run, and only one of them is right — that is the keepdims bug from 1.3 in a new costume, and the tests use a non-square matrix so it cannot hide.

Every one is checked for shape

As in 1.3, the tests assert the shape as well as the values. Here the shapes carry meaning: (d_out, d_in) says what a transformation takes in and gives back, and a stack of layers is readable as a chain of those shapes.

What the tests check that you might not

  • Weighting by a basis vector picks out a column. Exercise 1 is checked with [1, 0] and [0, 1] as well as ordinary weights, because that special case is exercise 3 arriving early.
  • Squashing to fewer dimensions is still a transformation. A (1, 2) matrix turns every row into one number, and the shape of that answer is (n, 1) rather than (n,).
  • Which way a rotation turns. Counter-clockwise is the convention, and getting it backwards sends [1, 0] to [0, -1]. The test says so in its message.
  • A rotation preserves every length. Checked with np.linalg.norm on six random vectors, because a matrix that turns things and also stretches them is not a rotation.
  • 45° twice is 90° once. Composition, one exercise early, and a good check that your matrix is a rotation rather than something that merely gets [1, 0] right.
  • Order, in both exercises that have one. compose is tested against applying the two transformations one at a time, and the stack in exercise 7 is tested against layers applied in the order they are listed.
  • A real Python bool from exercise 4. The same trap as 1.2 exercise 6: np.all hands you something that prints True and fails is True.

Build each one in stages

Everything after exercise 2 is one or two operations. The habit from 1.3 still pays: write one operation, print its .shape, check it against what you predicted, then add the next.

For this lesson there is a second habit worth adding. When a transformation looks wrong, apply it to [1, 0] and [0, 1] and see where they went. That is two lines, and it tells you what your matrix actually does rather than what you meant it to do.

Then run the demo

Once all seven pass, run the file directly. It moves the four corners of a square through a scaling, a shear and a rotation, prints where the basis landed in each case, and then shows the same pair of transformations composed in both orders.

python lessons/01-foundations/04-transformations/exercises.py

The stretch, if you want it

stretch.py is optional and not scored, and this one is the most convincing file in the lesson. You collapse a whole stack of layers into a single layer — without algebra, by asking where the zero vector and the basis vectors go — and then break the collapse by putting tanh between the layers.

The two numbers you print are the argument for activation functions. Having measured them yourself is different from having been told.
